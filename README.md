# Тривога Київ (AlarmKyiv)

Android-застосунок: звукове оповіщення про повітряну тривогу та відбій у
Києві, яке звучить навіть у беззвучному/віброрежимі.

**⚠️ NEPTUN (neptun.in.ua) — неофіційне джерело даних.** Це публічний
безкоштовний агрегатор, не офіційна система цивільного захисту. Не
покладайтесь на цей застосунок як на єдине джерело інформації про тривогу.

## Як це працює

- **Доставка:** foreground-сервіс (`AlertService`) тримає постійне
  WebSocket-з'єднання до NEPTUN. Не FCM — Doze може затримати push на
  хвилини, для тривоги це критично.
- **Звук навіть у тиші:** `AudioAttributes.USAGE_ALARM` відправляє звук у
  потік «Будильник», який не глушиться беззвучним/віброрежимом. Канал
  сповіщень навмисно тихий (`setSound(null, null)`), звук програється
  вручну через `MediaPlayer` (`AlertSound.kt`).
- **Стійкість з'єднання:** реконнект з експоненційним backoff, watchdog за
  тишею потоку (heartbeat теж рахується) і REST-фолбек, поки WebSocket не
  відновиться (`NeptunClient.kt`).

## Структура

| Файл | Призначення |
|---|---|
| `Config.kt` | ендпоінти, тайминги, правило «це Київ» (`TARGET_KEYS`) |
| `NeptunClient.kt` | WebSocket-клієнт з реконнектом, watchdog, REST-фолбек |
| `AlertState.kt` | `MutableStateFlow` — міст між сервісом і UI |
| `AlertSound.kt` | програвання на `STREAM_ALARM` |
| `AlertService.kt` | foreground-сервіс, вирішує коли грати сигнал |
| `BootReceiver.kt` | автозапуск після перезавантаження |
| `MainActivity.kt` | Compose-екран: статус, тестові кнопки, список тривог по країні |

## Відомі незакриті питання

1. **`Config.TARGET_KEYS` — припущення, не підтверджено.** NEPTUN не
   документує точні значення `key`/`title` для Києва. `MainActivity`
   показує сирий список усіх активних тривог з їхніми ключами — звірте
   його з `Config.TARGET_KEYS` під час реальної тривоги і поправте за
   потреби.
2. **Точна форма відповіді NEPTUN не задокументована офіційно в цьому
   середовищі розробки** (пряме звернення до `neptun.in.ua/developers`
   було заблоковане мережевою політикою sandbox'а під час розробки).
   `NeptunClient.handleFrame()` розбирає JSON толерантно — шукає масив
   тривог у кількох імовірних місцях (`alertOblasts`, `alerts`, `areas`,
   `threats`), тому дрібні розбіжності в назвах полів не мають ламати
   парсинг, але варто звірити з офіційною документацією і поправити
   `REST_SNAPSHOT_URL`/парсинг за потреби.
3. **Звукові файли — плейсхолдери.** `res/raw/alert.wav` і `clear.wav`
   згенеровані програмно (синтезована сирена й двотональний сигнал
   відбою), щоб проєкт збирався. Рекомендується замінити на нормальні
   аудіозаписи сирени/відбою.
4. **Збірка не перевірена в цьому середовищі.** Пісочниця розробки
   блокує `dl.google.com` (звідти AGP і AndroidX-бібліотеки) політикою
   мережі, тому `./gradlew assembleDebug` тут не проходить далі
   резолву плагінів. Зберіть проєкт в Android Studio або в оточенні з
   доступом до Google Maven — весь інший код написаний і перевірений
   вручну.
5. **Не перевірено на реальному пристрої.** Потрібно: дозволити
   сповіщення (Android 13+ запитує дозвіл автоматично), «Зняти обмеження
   батареї» (кнопка є на екрані), виключити з «Не турбувати».

## Збірка

```bash
./gradlew assembleDebug
```

Потрібен доступ до `google()` і `mavenCentral()` репозиторіїв Gradle
(AGP 8.5.2, Kotlin 1.9.24, Compose BOM 2024.06.00, compileSdk/targetSdk 34,
minSdk 24).
